# SM-022/025 scheduler contract (Sprint 05)

Backend lifecycle owns one service per application database, independent of WebView. A short tick plans work; bounded synchronous Google collection runs on worker threads. Scheduling logic is a pure millisecond clock policy, allowing fake-clock tests without sleeps. Initial scheduling and recovery stagger due work across one interval; completion plans from actual completion, never replays missed intervals. Capacity warnings use duration/overdue state, without inventing observations during suspension.

The database lane supplies current-account eligible candidates (valid current selected scope with exact approved baseline), durable schedule rows, account control generation, atomic leases and operational transitions. Scheduler owns deterministic stagger; store keeps existing next-run dates until interval changes or crash recovery. DB lease CAS plus process-global coordinator prevent duplicate work. Native single-instance is an additional outer guard.

A process-global weak coordinator registry is keyed by normalized database path; one coordinator covers manual capture/check and automatic check. It admits at most three jobs total and one job per spreadsheet ID, across accounts. Independent temporary databases have independent admission. Whole registered checks own the permit through validation; internal capture does not acquire a second permit. RAII releases permits on every return/panic.

Cancellation is cooperative via shared atomic token and generation checks, before each HTTP read/batch, before AST work and before local persistence. A current account generation and registry revision are checked before commit. Pause cancels active automatic work and releases leases without creating an outage. Shutdown is voluntary and bounded by the outstanding HTTP timeout, with no forced process termination. No OAuth consent is initiated by scheduler; Sprint02 refresh is reused. AuthBusy/admission contention is deferred without failure transitions.

HTTP retry budget remains bounded. Retry-After is preserved without the old ten-second truncation; long server delays are returned as sanitized typed hints and persisted as scheduler deferral. Short retries use exponential backoff+jitter. No provider bodies or secrets enter errors. Operational failures are Indeterminate, never an invented integrity violation; recovery is a distinct transition. Existing integrity comparison and event identity remain the sole observation engine.

Proposed service interface: MonitoringService::start(runtime, callback)->Arc; wake(); pause/resume controlled through database account control; check_now(id) marks pending; shutdown() cancels and wakes. status() exposes safe DTOs from store. Callback signals frontend/native refresh, not scheduling. A Clock trait provides now_ms and jitter; policy tests inject fixed values. Worker execution can be substituted in tests.

Hourly retention uses the database's effective scope policy. Missing observations during suspension remain unknown. Capacity warnings use overdue queued work and observed execution duration.
