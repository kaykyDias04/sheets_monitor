# Sprint 05 — app wiring evidence

Production startup uses `desktop::builder` (single-instance before setup), one IntegrationRuntime, one MonitoringService and one NotificationService. `NativeNotifier` receives persisted outbox rows; an action callback resolves the opaque notification ID for the currently connected account under the current authentication generation before showing the existing window and emitting `notification:open`. The frontend performs its own fresh account/generation check before displaying details. No callback chooses an account or initiates OAuth.

Tray actions enqueue checks or persist control through the same backend paths as IPC. Action callbacks dispatch database work outside the UI thread. Current read-only Sheets and optional Script grants filter both eligible counts and queued files. `monitoring_check_file` additionally checks registry revision. `request_check_for` scopes queued items by subject/generation; a queued request for the new account survives a tick still remembering the old account, and queued old generations are discarded.

Lifecycle wiring registers the shell before allowing close behavior and handles RunEvent::ExitRequested through its bounded cleanup policy. Explicit exit cancels monitoring, drains notifications for up to two seconds and monitoring for up to two seconds outside the UI thread. Startup never modifies registration. `--from-autostart` hides the window only after a tray exists, the actual startup entry is registered and managed, and the current account opted into run_minimized. Vault errors preserve an accessible shell and actionable authentication state.

Service completion/mutations/preferences emit `monitoring:changed` without private payload, wake the dispatcher, and refresh the tray status. No frontend timer drives checks. `desktop:navigate` carries only settings/overview; the notification action event carries only an opaque internal ID.

Executed: `cargo check --manifest-path src-tauri/Cargo.toml --target x86_64-pc-windows-msvc --lib` passed (7.70s). `scheduler-gate2-tests.log` records12 scheduler tests passed, including the identity-scoped queue regressions. `app-wiring-tests.log` records2 desktop tests passed (0.06s), including current read-only Sheets/Script permission filtering against registered synthetic resources. These source/unit checks do not establish Windows notification display or native lifecycle behavior; native QA is separately owned by the principal.
